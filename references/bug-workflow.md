# Bug 流程

修 bug：**复现 → 假设树 → 最小补丁 → 证据**。Map 未 complete（且非合法 fast path）禁改业务代码。

## 闸门顺序

```
Map complete → 复现/确认 → 假设树排序 → 低成本证伪 → 最小补丁 → 再复现 → 证据 ≥ L1 → Leave
```

## 1) 复现

| 手段 | 何时 |
|------|------|
| 本地复跑用户步骤 | 有环境 |
| 用户确认的日志/录屏（脱敏） | 难本地化 |
| 最小复现用例 / 失败测试 | 可自动化时优先 |

做不到复现且用户未书面确认现象 → `blocked`，**禁止瞎改**。  
在 `change.md` **验证**写清：复现命令/步骤、改前失败表现。

## 2) 假设树（可证伪）

从 Map 的「已证实 / 假设 / 未知」抽出 **2–5 条**可证伪假设，按成本排序：

1. **读日志 / 看栈**（最低）
2. **定向读码 / 二分触点**
3. **加临时探针或失败测试**（勿长期留噪声）
4. **改码试探**（最后手段；仍须在改动边界内）

每条假设写：若真会看到什么、如何证伪。先测成本最低的；一条被证伪就划掉，更新 Map 假设区。

**禁止**：无假设树就「感觉在这」大面积改。

## 3) 最小补丁

- 只动 Map **改动边界**内、能消灭该复现的最小 diff
- 同文件同模式可一并列入边界（须在 Map 写明）；禁顺手重构 / 顺手加功能
- 发现根因在边界外 → **停手**，更新 Map，问用户后再扩

## 4) 证据落点

| 等级 | bug 含义 | 可宣称完成？ |
|------|----------|--------------|
| L0 | 「应该好了」无再复现 | **否** |
| L1 | 同一复现步骤：改前失败、改后通过（可手工） | **是**（默认最低） |
| L2 | 失败测试改红→绿，或自动化回归 | **是**（优选） |

`change.md` 必填实质：**改动摘要** + **验证**（步骤 / 前 / 后）。能补测则冲 L2。

## 5) Change 检查清单（短）

- [ ] 复现步骤可复跑（或用户确认现象）
- [ ] 假设树至少测过成本最低的一条并有结论
- [ ] diff 在边界内且意图单一
- [ ] 改后同一复现路径通过；证据 ≥ L1
- [ ] 未顺手重构；未知写进 notes

## 失败兜底

| 触发 | 处理 |
|------|------|
| 无法复现 / 缺环境 | `blocked` + 精确诉求；不改码 |
| 假设全否、根因仍不清 | 写未知，问用户；勿 L0 宣称完成 |
| 补丁后复现仍红 | 回滚或修订假设；保持 `in_progress` |
| 范围膨胀到「重写模块」 | 停手，拆任务或改 type |
