# Map 指引

地图保持**任务范围**。不要整仓考古。

## 建议顺序

1. 定位症状或功能区的运行时/配置入口
2. 沿一条关键路径留下 文件:符号 面包屑
3. 列出最热符号的 fan-in 调用方（影响面）
4. （可选）对关键触点看一眼 git 线索 — 见下文
5. 区分已证实事实与猜测
6. 改码前冻结较小的改动边界

## 好的路径写法

`HTTP /login` → `AuthController.login` → `SessionService.create` → `RedisStore.set` → 失败于 TTL 配置

## 差的地图

- 只有目录树倾倒
- 「感觉是鉴权问题」却无文件
- Unknowns 仍挡住修复却标 `complete`，也不问用户
- 把整段 `git log` 当 Map（本 skill **不是** git 故事 / 技术债报告工具）

## 深度与模式

- `delegate`：能支撑可审改动的最短路径
- `onboard`：同路径 + 每一跳一句角色说明

---

## 何时看 git（轻量线索）

**先**靠运行时/代码链路定位触点；git 只给**已入 Touch list 的文件**加点上下文，可选，**不计入 Map DoD**。

### 适合看一眼时

- 不知这段代码「谁常改 / 是否刚被碰过」，影响改动边界或复现猜测
- onboard：新人需要知道热点作者或近期 churn 才能问对人
- 怀疑近期回归：对触点看最近几次提交主题（仍须用复现/测试验证，**提交信息 ≠ 根因**）

### 不要看 / 看完就停时

- 还没找到入口与关键路径 — 先 Map 代码，别先考古全仓历史
- 想写「仓库编年史」「技术债长文」— **超出本 skill**；另开文档任务或别的 skill
- 用 blame 点名问责 — 禁止；作者字段只作「可能知情的人」线索
- 无 git 仓 / 浅克隆无历史 — 在 Map 写 `N/A（无历史）`，不影响 complete

### 建议命令（仅对触点路径，限条数）

```bash
# 近况与主题（示例：最近 10 条）
git log -n 10 --oneline -- path/to/file

# 提交次数粗看 churn（可选）
git rev-list --count HEAD -- path/to/file

# 热点作者（可选，勿用于问责）
git shortlog -sn -- path/to/file | head -5
```

### 如何写进 map.md

填可选段 **Git 线索（可选）**：每个关键触点最多 1–3 行（近期主题 / churn 粗量 / 热点作者）。  
写明「仅线索」；**不得**仅凭 git 就把假设标成已证实，也**不得**因看了 git 就扩大改动边界到「顺便清理该作者改过的一切」。
