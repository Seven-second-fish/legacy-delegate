# Refactor 流程（轻量闸门）

本 skill 的 refactor **默认只做轻量、行为保持**。缺表征锁或回归计划时，不得宣称完成。

## 允许（轻量）

- 已映射边界内：抽函数 / 局部重命名 / 去重
- 移动代码时，**同一改动**内更新明确调用方
- 缺测试时：行为保持型改动前先补**表征测试**或等价手工基线

## 禁止（推迟 / 问用户）

- 跨模块重设计、换层、依赖倒置运动
- 修 bug / 加功能时「顺便重构一切」
- 无回归计划、无回滚点的重构
- 改变对外行为却标 `type: refactor`（应改 type 或拆任务）

## 闸门顺序（硬）

```
Map complete → 行为锁（表征）→ 小步改码 → 重跑回归 → 证据 ≥ L1 → Leave
```

未完成「行为锁」前**禁止**改业务代码（可先只加表征测试/清单，不算进入大 refactor）。

## 1) 表征测试 / 行为锁

在改结构前，先固定「改完必须仍为真」的行为：

| 手段 | 何时 | 记在哪 |
|------|------|--------|
| 自动化表征测试（优先） | 仓内已有测试框架 | `change.md` **表征证据** + 可冲 L2 |
| 手工基线清单 | 暂无自动化 | **表征证据**写清输入/输出/副作用；证据多为 L1 |
| 用户确认的现状录屏/日志 | 难自动化的 UI/集成 | 脱敏后贴步骤；仍须可复跑 |

**行为锁 DoD（至少一项实质内容）：**

1. 锁住的行为是什么（1–3 条可观察断言）
2. 如何在改前跑通基线（命令或步骤）
3. 改后用**同一套**步骤复跑

没有基线就开抽函数 → **🛑 停止**，先补表征。

## 2) 回归清单

Map 阶段或 Change 计划中列出（可短）：

- [ ] 表征测试 / 基线步骤
- [ ] 触点调用方冒烟（Map 影响面里点名的）
- [ ] 用户成功标准相关路径
- [ ] （可选）构建 / lint

宣称完成前，清单项须在 `change.md` **验证**里跑过并留下前后对比。

## 3) 小步与回滚点

- 一组 diff 一个意图（例如「只抽纯函数，不改调用约定」）
- 在 `change.md` **回滚点**写清：如何撤回（`git revert` / 还原文件 / 特性开关）
- 范围膨胀 → 停手，更新 Map 边界，**🔴 检查点**问用户

## 4) 证据等级（refactor 默认）

| 等级 | refactor 含义 | 可宣称完成？ |
|------|---------------|--------------|
| L0 | 只说「结构更清晰」无复跑 | **否** |
| L1 | 同一套基线/清单改前绿、改后绿（可手工） | **是**（默认最低） |
| L2 | 表征测试自动化通过 | **是**（优选） |

`evidence_grade` 默认目标 **≥ L1**；能补测试则冲 L2。

## 5) Change 产物必填（type: refactor）

除通用段外，必须实质填写：

1. **表征证据** — 基线是什么、改前如何证明  
2. **回滚点** — 如何一键或短步骤撤回  
3. **验证** — 改后复跑同一基线（前后对比）  
4. **改动摘要** — 仅边界内文件  

检查脚本在检测到 `type: refactor` 时会校验表征/回滚章节非空壳。

## 失败兜底

| 触发 | 处理 |
|------|------|
| 无法建立基线 | `blocked` 或问用户要可观察行为；不改结构 |
| 改后基线红 | 回滚或修到绿；勿在红态宣称完成 |
| 发现必须改行为 | 停 refactor；改 `type` 或新开 bug/feature 任务 |
| 想做跨模块大改 | 说明超出轻量范围；设 `aborted` 或拆方案问用户 |
